# OncoPilot 肿瘤入院记录草稿助手 V0.11.1

OncoPilot 是一个面向肿瘤科接管场景的医疗 AI 作品：把经授权并完成身份字段去标识化的真实临床资料或合成资料，整理为有来源、有时间顺序、可人工确认的入院记录草稿，并分阶段生成诊断与下一步参考。

- 在线体验：[oncopilot.rtflowai.top](https://oncopilot.rtflowai.top)
- 版本记录：[CHANGELOG.md](./CHANGELOG.md)
- 问题与建议：[GitHub Issues](https://github.com/longjianw/oncopilot/issues)

> 当前是公开测试版和求职作品，不是医疗器械，不连接医院信息系统，也不能替代有资质医生作出诊断、治疗或最终病历审核。

## 为什么做这个项目

肿瘤患者常有跨医院、跨年度、多线治疗的长病程。一次性让模型同时写主诉、现病史、诊断和计划，容易漏掉治疗线次、混淆本次与既往就诊，或把缺失信息写成确定事实。OncoPilot 将这件事拆成可检查的阶段：

1. 建立临床事件账本，保留时间、来源、本次/既往归属与证据强度。
2. 先生成主诉、现病史、背景病史和专科查体草稿。
3. 独立生成初步诊断、依据与真正会改变判断的缺口。
4. 诊断阶段通过后，再生成当前优先问题、下一步与理由。
5. 医生可针对某一候选继续追问，并将确认后的内容填入可编辑草稿。

模型输出未通过完整性或安全门禁时，系统会重试或明确提示失败，不用程序内置的通用候选冒充病例专属结论。

## V0.11.1 已实现

- 临床事件账本：覆盖初次诊断、每线治疗、复发进展、近期治疗、急性起病、外院处理、本次到院及背景病史。
- 分阶段模型调用：病史、诊断、计划分别生成，诊断可先展示，不必等待整套内容。
- 主诉与现病史完整性门禁：关键时间桶遗漏、外院查体混入现病史、本次/既往错位时不直接展示。
- 背景病史前置：高血压、糖尿病、冠心病、无关旧手术、长期用药和过敏史在诊断与计划前可见。
- 候选确认机制：未询问不等于阴性，未查体不等于正常；候选项只有医生确认后才进入草稿。
- 病例继续追问：优先给一个方向及理由，再列条件性备选、决策改变因素和一个最值得继续问的问题。
- 图像和 PDF 资料入口：支持多页转录、单页失败重试与实际模型标记。
- 来源核验入口：区分模型初稿、本地来源卡和已读取的权威网页，不把未接入资料写成已核验。
- 敏感标识拦截：演示环境拒绝常见姓名、住院号、手机号、身份证号和二维码等可识别信息。

## 质量证据

当前自动化验证包括：

- 38 项代码与渲染测试。
- A01–A11 入院记录合成回归，覆盖时间线完整性、治疗线次、本次/既往错位、证据升级、Markdown 污染、外院转诊结尾、外院查体混入、IHC 与分子检测混淆等风险。
- R01–R02 诊断与下一步参考回归。
- 生产构建、桌面浏览器和移动端布局检查。

以上均使用完全合成资料，只证明当前工程门禁和演示流程通过，不代表临床有效性、真实医生节时、模型稳定性或医疗器械合规性。

## 隐私与公开边界

- 可以使用已取得必要授权并完成身份字段去标识化的真实临床资料进行测试。
- 姓名、住院号、身份证号、电话、地址、二维码和原始身份截图不得进入公开 Issue、截图或日志。
- 输入内容会发送给服务端配置的第三方模型完成处理；本项目不承诺第三方服务适用于真实医疗数据。
- 仓库只保留合成回归样例，不包含运行密钥；密钥仅通过部署环境变量提供。
- AI 输出必须由有资质医生结合原始资料逐项核对。

公开反馈请阅读 [CONTRIBUTING.md](./CONTRIBUTING.md)，并始终用合成案例复现问题。

## 本地运行

需要 Node.js `>=22.13.0`。

```bash
npm install
cp .env.example .env.local
npm run dev
```

真实模型调用需要在服务端配置 `.env.example` 列出的火山方舟环境变量。文本事实抽取、正式草稿、重新合成、诊疗参考和病例追问默认使用 `deepseek-v4-pro`；图片转录使用独立的多模态模型配置。密钥不得提交到仓库或发送到客户端。
