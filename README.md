# OncoPilot 肿瘤入院记录草稿助手

一个面向医疗 AI 求职展示的轻量可交互作品。医生第一次接管一名肿瘤相关患者时，把少量资料变成安全模板骨架，通过“选择 + 填空”补全病史、症状和查体，再由 AI 重新合成为可编辑草稿。

## 当前版本

- 单一流程：资料 + 可选本次来院目的 + 本次到院关系 → 结构化事实 → 模板骨架 + 候选选择项 → 医生选择/填空 → AI重新合成 → 可编辑草稿
- 真实接入火山方舟 Coding Plan；当前主病历链的结构化事实抽取与正文生成均使用服务端配置的 `deepseek-v4-pro`，重新合成和诊疗参考同样默认使用 Pro；只有独立的文书核对对话可由医生手动切换 V4 Flash
- 输出主诉、现病史、既往史、个人史、家族史、过敏史和专科体格检查；另设可编辑诊断/计划整理区，将医生已明确内容与待核对的 AI 参考候选分层显示
- 先抽取来源、时间、既往/本次归属和证据强度，草稿生成器只能使用已通过结构校验的事实；单段事实抽取失败会由 V4 Pro 自动重试一次，连续两次失败即停止本轮生成，不再用程序规则或 RAW 待复核片段冒充模型事实
- 低信息输入不再只返回空白框；未提供模块显示带方括号的安全骨架，并按肿瘤类型给出候选阳性/阴性症状和查体选项
- 候选内容默认不进入病历，只有医生点击确认后才加入对应草稿；未询问不等于阴性，未查体不等于正常
- 只有确实需要补充细节的选项才显示输入框，并使用与该问题/选项匹配的提示；点击“一键重新整理草稿”后，AI只用当前草稿和医生确认项去重并重组，不新增事实
- 提供“问 AI · 文书核对”对话窗口，用于解释某项该问什么、查什么和怎样记录；回答按生成进度逐段显示，显示实际等待秒数并渲染重点加粗，它不替患者回答，也不作诊断、分期或治疗建议
- 自由填空会自然融入已选句子，不再机械追加“补充记录”；仍可一键重新整理全文
- 黑色素瘤专科查体提供病灶/瘢痕、周围皮肤、颈部/腋窝/腹股沟淋巴结、ECOG PS和疼痛NRS的可改写模板；影像/病史异常只能提醒实际查体，不能改写成已触诊阳性
- 诊断与计划区可由医生直接编辑，草稿重新合成不会自动改写这两个模块
- 诊断与计划旁新增独立“AI参考候选”：由 V4 Pro 根据每份病例的结构化事实生成初步诊断表达、依据、待补前提、候选检查和分层诊疗方向；每项均标注适用条件和目的
- “诊断与下一步”首屏只保留初步诊断、关键依据、待补前提和主要条件分支；医生可继续问整个病例，也可从某一项继续追问，系统自动带入当前结构化事实、来院目的、上一轮候选和该窗口的短对话历史
- 药物追问只输出与当前病例相关的药物类别或代表药物候选、适用/排除条件，以及开立前必须核对的完整执行字段：过敏史、肝肾功能、病原学、既往用药、院内规格、单次剂量、频次、稀释液、总体积、输注时间、配伍和复评节点；未接入并审核本院药品字典、说明书或抗菌药方案来源时，不展示可直接发送的剂量、频次、配液或输注医嘱
- 药物追问优先原样展示通过门禁的 V4 Pro 回答；若纠偏模型空返回、超时或仍越界，只保留本轮模型文本中可安全提取的病例候选，并明确标注“V4 Pro候选已删除未核验细节”和“系统补充的待核对字段”，不从旧候选或程序规则新造治疗方向
- 不再用程序内置快速候选抢先占位；模型未完成或输出未通过门禁时明确提示重试，不展示程序规则拼接稿或跨病种通用套话
- AI参考默认不进入正式草稿；医生可主动填入诊断/计划整理，并保留“待医生核对”标记
- 提供“CSCO来源卡核验”和“联网核验权威网页”两条路径；只显示本次确实读到或已经完成页码提炼的来源，不把未接入书籍或抓取失败写成已核验
- 影像中的“考虑/可能”等不确定性必须保留；既往住院、出院和未来计划不得写成本次经过
- 病历正文门禁会拦截主诉以“转入/进一步诊治”等半句话收尾、资料未提供的自造持续时间、外院转诊意见晚于本次收治事实，以及外院/转院前/出院前查体冒充本次专科查体
- 增加“本次到院关系”选择：外院“建议转院”只能写成既往经过；资料或医生已确认转入我院时，现病史必须在外院转诊意见之后以本次到院/收治事实收束
- 覆盖肿瘤科接管的实体瘤、淋巴瘤和白血病患者，不要求患者是第一次住院
- 不再展示没有实际功能的患者列表或“进入管床”页面
- 支持手机拍照或上传图片、HEIC 和 PDF；图片不是在浏览器内做传统 OCR，而是逐页发送给已配置的豆包多模态模型忠实转录，再进入同一入口
- 多页 PDF 以最多 3 页并发转录；单页超时不阻断已成功页面，页面可单独重试并显示实际使用的视觉模型
- 长资料按来源页分段抽取后合并；任一分段连续两次未返回通过校验的结构化事实即停止整份草稿生成，页面保留原输入供重试，但不把规则提取或 RAW 片段继续送入正文生成
- A01-A10 入院记录合成回归包覆盖当前就诊错位、证据升级、Markdown污染、既往出院诊断、外院转诊结尾和外院查体混入；任何 P0 均判失败
- A01 已包含结构化输入、项目参考答案、错误标签、候选输出合同和可重复评分脚本
- 曾完成 A01 完全合成单病例的五模型连通性与评分初测；该结果不代表临床有效性、稳定时延或真实医生节时
- 不连接医院系统；演示版不使用、保存或公开可识别患者信息

## 本地运行

需要 Node.js `>=22.13.0`。

```bash
npm install
npm run dev
```

真实模型调用需在服务端配置 `.env.example` 中列出的火山方舟环境变量。当前部署的文本事实抽取、正式草稿、重新合成、诊疗参考和病例继续追问均使用 `deepseek-v4-pro`；图片转录默认复用 Coding Plan 的 `ARK_CODING_API_KEY`，但调用独立的 `doubao-seed-2.1-turbo` 多模态模型。`ARK_VISION_MODEL` 可显式锁定视觉模型，`ARK_VISION_*` 其余变量仅在切换到另一套视觉服务时覆盖。密钥不得提交到仓库或发送到客户端。

检查构建与测试：

```bash
npm run lint
npm run eval:admission
npm run eval:reference
npm test
```

## 安全边界

本项目仅用于作品展示、学习和辅助评测，不可用于真实临床决策。AI 输出不能代替有资质的放疗医师完成治疗决定或最终审核。

图片识别会将图片发送给配置的视觉模型，因此演示版不得上传含姓名、住院号、二维码、电话、身份证号或其他可识别信息的真实患者图片。
