# OncoPilot 肿瘤入院记录草稿助手

一个面向医疗 AI 求职展示的轻量可交互作品。医生第一次接管一名肿瘤相关患者时，把已有资料整理成一套可编辑、待医生核对的入院记录草稿包。

## 当前版本

- 单一流程：粘贴/上传资料 + 可选填写本次来院目的 → 结构化事实抽取 → 入院记录草稿包 → 医生核对
- 真实接入火山方舟 Coding Plan 的 `deepseek-v4-flash`
- 输出主诉、现病史、既往史、个人史、家族史、过敏史、专科体格检查，以及医生已明确判断后的诊断/计划整理
- 先抽取来源、时间、既往/本次归属和证据强度，草稿生成器只能使用已通过结构校验的事实
- 未询问的阴性症状、未提供的病史和未完成的查体保持空白或待核对，不自动写“否认”“无特殊”或“正常”
- 影像中的“考虑/可能”等不确定性必须保留；既往住院、出院和未来计划不得写成本次经过
- 覆盖肿瘤科接管的实体瘤、淋巴瘤和白血病患者，不要求患者是第一次住院
- 不再展示没有实际功能的患者列表或“进入管床”页面
- 支持手机拍照或上传图片、HEIC 和 PDF；图片先转成待核对文字，再进入同一入口
- A01-A03 入院记录合成回归包覆盖当前就诊错位、证据升级和无来源查体/病史补写；任何 P0 均判失败
- A01 已包含结构化输入、项目参考答案、错误标签、候选输出合同和可重复评分脚本
- 已完成火山方舟五模型单病例初测；Flash 与 Pro 在 A01 均为100分，Flash更快
- 不连接医院系统；演示版不使用、保存或公开可识别患者信息

## 本地运行

需要 Node.js `>=22.13.0`。

```bash
npm install
npm run dev
```

真实模型调用需在服务端配置 `.env.example` 中列出的火山方舟环境变量。图片识别默认复用 Coding Plan 的 `ARK_CODING_API_KEY`，但调用独立的视觉模型；`ARK_VISION_*` 仅用于覆盖为另一套视觉服务。密钥不得提交到仓库或发送到客户端。

检查构建与测试：

```bash
npm run lint
npm run eval:admission
npm test
```

## 安全边界

本项目仅用于作品展示、学习和辅助评测，不可用于真实临床决策。AI 输出不能代替有资质的放疗医师完成治疗决定或最终审核。

图片识别会将图片发送给配置的视觉模型，因此演示版不得上传含姓名、住院号、二维码、电话、身份证号或其他可识别信息的真实患者图片。
