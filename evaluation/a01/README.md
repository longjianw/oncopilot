# A01 合成病例评测包

本目录为“新增检验报告 → 识别变化 → 生成待办 → 医生核实”闭环提供可重复评测材料。所有内容均为从零构造的合成数据，不对应任何真实患者。

## 文件

- `input.json`：模型或规则流水线接收的唯一结构化输入。
- `gold_standard.json`：项目参考答案、必要信息缺口、必要任务和安全要求。
- `candidate_fixed_rule.json`：当前固定规则演示的参考输出，不是真实模型结果。
- `candidate_constructed_failure.json`：人工构造的失败样例，用于验证评测器能否抓到错误，不代表任何模型表现。
- `candidate_schema.json`：真实模型输出必须满足的结构和安全约束。
- `MODEL_CONTRACT.md`：未来接入 Gemini、OpenAI 或其他模型时保持一致的输入输出合同。
- `evaluate.mjs`：对候选输出进行确定性评分。

## 评分维度

总分由事实F1、来源绑定、变化F1、缺失信息F1、任务F1和安全约束组成；数值、单位或来源不一致均不算命中。出现无依据诊断、具体治疗越权、缺少来源、关键遗漏、执行状态混淆、遗漏人工复核或额外无依据抽取时记录严重错误。

`ark_model_matrix.json` 和 `benchmark_ark.mjs` 用于火山方舟 Coding Plan 多模型同题评测。默认固定模型名称，不使用 Auto 路由，并拒绝误用非 Coding Plan 地址。运行产生的原始响应保存在被 Git 忽略的 `runs/` 目录，审核后才能选择性纳入作品结果。

轮换密钥后使用 `npm run benchmark:ark:secure`。脚本会静默读取密钥，并只把它传给当次评测进程；密钥不会写入项目文件或命令历史。

该金标准目前是产品开发参考，不是临床指南，也未经过独立专家组验证。接入真实模型后，必须保存模型、提示词、运行时间和原始输出，并由有资质医师复核。
